# 🚀 Argo CD Application Creation — Full Guide with Emojis

This guide shows how to fill the **Argo CD Application form**, and how to do the same with **CLI (imperative)** and **YAML (declarative)** — all with 💡 explanations, ✅ tips, and ⚙️ examples.

---

## 🧩 GENERAL SECTION — Form Fields Explained

### 🔹 Application Name

- Unique name for your app in Argo CD.
  👉 Example: `bankapp`

### 🔹 Project Name

- Logical group in Argo CD for apps with shared permissions or clusters.
  👉 Example: `default`

### 🔹 Sync Policy

- **Manual:** Sync manually (safe for production).
- **Automated:** Auto-sync when Git changes.

✅ Recommended: **Automated** for GitOps.

### 🔹 Set Deletion Finalizer

- Prevents resource deletion when you delete the Argo CD App.
- ❗Leave OFF unless you want to keep resources even after deleting the app.

### 🔹 Sync Options

| Option                    | Meaning                                      |
| ------------------------- | -------------------------------------------- |
| ✅ Skip Schema Validation | Skip strict schema checks for unknown CRDs   |
| ✅ Auto-Create Namespace  | Create the namespace if missing              |
| ✅ Prune Last             | Delete old resources after applying new ones |
| ✅ Apply Out-of-Sync Only | Only apply changed resources                 |
| ✅ Server-Side Apply      | Use server-side apply (modern, safer)        |
| ❗ Replace                | Delete & recreate (may cause downtime)       |

### 🔹 Prune Propagation Policy

- `foreground` (waits for dependents to delete)
- `background` (faster, deletes asynchronously)

✅ Recommended: `foreground`

## ⚙️ Imperative Method (CLI)

Run these commands to create and sync the app via CLI 🖥️

```bash
# Create Argo CD Application
argocd app create bankapp \
  --repo https://github.com/bernardofosu/Mega-Project-CD-main.git \
  --path Manifest \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace webapps \
  --sync-policy automated \
  --project default

# Sync app manually (forces deployment)
argocd app sync bankapp --prune --force
```

✅ **Pros:** Quick setup
❌ **Cons:** Harder to track in Git (not fully GitOps)

## 📄 Declarative Method (YAML in Git)

Add this to your repo (e.g., `apps/bankapp.yaml`) 📁

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: bankapp
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/bernardofosu/Mega-Project-CD-main.git
    targetRevision: main
    path: Manifest
  destination:
    server: https://kubernetes.default.svc
    namespace: webapps
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - PrunePropagationPolicy=foreground
      - ServerSideApply=true
```

💡 Commit this YAML to your repo and Argo CD will automatically detect and apply it.

✅ **Pros:** Full GitOps compliance
❌ **Cons:** Requires initial setup in Git

## 🔍 Compare & Sync (Git vs Cluster)

### 🧮 Compare Differences

```bash
argocd app diff bankapp
```

Shows the difference between Git (desired state) and cluster (live state).

### 🔁 Sync Changes

```bash
argocd app sync bankapp --prune --force
```

Applies all differences to the cluster.

---

## ⚡ Useful Tips

- 🧠 **SelfHeal** → Argo CD auto-fixes manual cluster changes.
- 🧱 **Prune** → Deletes resources no longer in Git (careful with PVCs).
- 🔐 **ServerSideApply** → Fewer merge conflicts.
- 🪄 **Auto-Create Namespace** → Saves you a `kubectl create ns` step.

```bash
argocd app rollback bankapp <REVISION>

argocd app delete bankapp --cascade
```

---

## ✅ Best Practices

1. Always use **Server-Side Apply** ✅
2. Enable **SelfHeal + Prune** only if Git is single source of truth 🧠
3. Use **foreground pruning** for stateful apps ⚙️
4. Exclude PVCs from prune via `resource.exclusions` 🧱
5. Store `Application` YAMLs in Git for true GitOps 🔁
